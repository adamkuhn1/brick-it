# Lego MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Local app: photo → TripoSR mesh → LEGO brick build (Build JSON) → 3D viewer + instruction booklet + LDraw/BrickLink/CSV exports.

**Architecture:** `engine/` is a pure Python package (numpy + trimesh) with one module per pipeline stage and `engine.build(mesh, size_studs) -> Build`. `server/` is FastAPI wrapping TripoSR (optional, lazily imported) + mesh cache + engine. `web/` is Vite + React + react-three-fiber consuming Build JSON.

**Tech Stack:** Python 3.12, uv workspace, numpy, trimesh, scipy, FastAPI, uvicorn, Pillow, pytest; TripoSR + rembg + torch (optional `model` extra); TypeScript, Vite, React 18, three.js, @react-three/fiber, @react-three/drei, vitest.

**Spec:** `docs/superpowers/specs/2026-10-15-lego-design.md`

## Global Constraints

- No cloud AI APIs. Only ML: TripoSR + bundled rembg, run locally.
- `engine/` has no web or model imports.
- Build JSON shape exactly as spec §3; `z` in plate units, always multiples of 3; `rot` ∈ {0, 90}.
- Brick vocabulary: 1×1 3005, 1×2 3004, 1×3 3622, 1×4 3010, 1×6 3009, 1×8 3008, 2×2 3003, 2×3 3002, 2×4 3001, 2×6 2456, 2×8 3007.
- Default filler color: Light Bluish Gray.
- Size slider 8–32 studs, default 16. Builds ≤ 12 studs stay solid.
- Memory budget: 8 GB M2 (MPS, CPU fallback).
- Image rejection: < 256 px, near-blank, low Laplacian variance. Mesh rejection: empty or thinnest bbox axis < 10% of largest.
- Warning when > 2,000 bricks.
- One setup command `./scripts/setup.sh`, one run command `./scripts/dev.sh`.

## Review Focus

1. Mesh with no vertex colors (plain `.obj` upload) → build still succeeds using a default color, no crash.
2. Mesh whose up axis is Y (TripoSR/glTF convention) → model must stand upright, not lie on its side.
3. Very thin or tiny mesh at size 8 → at least one brick produced; never an empty build or division by zero.
4. Repeated slider changes → same `mesh_id` + size returns deterministic identical builds (cache-safe).
5. TripoSR not installed → server starts, `/api/meshes` with a photo returns a clear 503-style error, `.glb` upload still works.

Each of these is pinned by a test in the owning task (Tasks 1, 1, 3, 6, 7).

## Tasks

### Task 0: Workspace scaffold + model check
- Create uv workspace, engine/server packages, `scripts/setup.sh` (uv sync, clone TripoSR into `vendor/TripoSR`, weights fetched on first run by HF hub), `scripts/dev.sh`.
- Model check: try installing torch + TripoSR deps; record result in README. If install fails, `.glb` path remains.
- Commit.

### Task 1: Types + voxelize
- **Produces:** `voxelize(mesh: trimesh.Trimesh, size_studs: int, up: str = "y") -> Voxels` where `Voxels(occ: bool[X,Y,Z], rgb: uint8[X,Y,Z,3], has_color: bool)`.
- Tests: unit cube at size 8 → grid 8×8×~7 (8 mm/9.6 mm), fully filled; Y-up tall box ends up tall in Z (Review Focus 2); mesh without colors → `has_color False`, rgb gray (Review Focus 1).

### Task 2: Colors
- **Produces:** `PALETTE: list[Color]`, `nearest_color(rgb) -> int`, `colorize(vox) -> int16[X,Y,Z]` (palette index; -1 empty; -2 don't care set later).
- Tests: pure red → Red; specks smoothed; ΔE in Lab.

### Task 3: Hollow
- **Produces:** `hollow(colors: int16 grid, size_studs) -> int16 grid` with interior = `DONT_CARE (-2)`, removed = -1.
- Tests: solid cube size 16 → interior removed, shell intact; size ≤ 12 unchanged; support columns present under roof of a wide hollow box; tiny mesh at size 8 yields ≥1 voxel (Review Focus 3).

### Task 4: Layout
- **Produces:** `layout(grid) -> list[Brick]` (x,y in studs, z in plates = layer*3).
- Tests: every occupied cell covered exactly once; every brick in vocabulary; each brick single color (ignoring don't-care); seam stagger ratio > 0.5 on a solid block.

### Task 5: Structure
- **Produces:** `repair(bricks, grid) -> (bricks, warnings)`, `components(bricks) -> list[set[int]]`.
- Tests: cube/arch/T → one component; floating-island case → warning or fixed; COM warning on overhang.

### Task 6: Steps, exports, `engine.build`
- **Produces:** `plan_steps(bricks) -> list[Step]`, `to_ldraw/to_bricklink_xml/to_csv`, `build(mesh, size_studs) -> Build`, `Build.to_json()`.
- Tests: every step buildable from prior steps; LDraw lines parse; XML well-formed; build deterministic (Review Focus 4); end-to-end on sphere, L-shape, arch, T.

### Task 7: Server
- Routes per spec §3 data flow; job thread; cache by sha256; checks.
- Tests (TestClient): upload `.glb` → done → build → three exports; blurry/tiny image rejected; photo with model unavailable → error message (Review Focus 5).

### Task 8: Web — capture, generating, result viewer
- `api.ts`, `types.ts`, Capture (drop/picker/webcam), Generating (poll), Result (r3f instanced bricks w/ studs, slider debounced, stats, warnings, downloads, tabs).
- Tests: `tsc --noEmit`, vitest smoke rendering from fixture Build JSON.

### Task 9: Booklet
- Offscreen three.js renderer, toon shading + outlines, isometric camera; cover, 2–4 steps/page, parts callouts, inventory; A4 print CSS.

### Task 10: README + write-up, verification in browser.
